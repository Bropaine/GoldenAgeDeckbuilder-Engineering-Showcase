# UI architecture: expressive comics, stable information

[Back to showcase](../README.md)

The presentation follows a restored Golden Age comic direction: strong ink, paper surfaces, selective halftone, and limited semantic color. Its governing principle is readable decision information. Costs, health, intent, targets, and choices remain stable while decorative feedback supplies expression.

## Presentation consumes authority

Presenters read current runtime state, format it, and forward bound commands. Views handle Unity references, input, layout, and feedback. Damage arithmetic, persistent deck mutation, health settlement, and encounter advancement remain in runtime services.

Feedback consumes completed-command results rather than reconstructing events from displayed totals. This preserves the difference between an executed enemy action, its upcoming intent, and its current state.

## Repeated enemy units

Multi-enemy presentation uses durable repeated units bound to exact Battle-local entries. Stable defeated slots preserve spatial context and action order. Stat inspection identifies the exact originating unit; selecting a unit forwards its runtime-bound target request.

Presentation selection may be cleared or rebound when a Battle changes. The runtime still validates the eventual command, so UI timing does not decide authority.

## Visual hierarchy

The approved visual standard places comic texture outside dense information areas. Color has semantic roles, while labels and values carry explicit meaning. Art and impact lettering frame decisions without covering rules or target boundaries.

This is an authored readability standard, not a claim of measured accessibility compliance. The accepted input evidence is mouse/pointer click and hover; keyboard/controller support is not established by this checkpoint.

## Evidence and boundaries

The supplied accepted record covers repeated enemy presentation, card-first targeting, stat inspection, bounded help, and battle-stage composition. It records specific multi-enemy presentation checks at 1280×720 and 1920×1080. Separate standalone display evidence exists for other modes, but does not imply every layout or display configuration has been tested.
